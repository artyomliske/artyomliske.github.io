# Портфолио — Артём Лиске

Одностраничный сайт-портфолио: автоматизация бизнес-процессов, шесть кейсов,
русская и английская версии, светлая и тёмная темы.

Статика без сборки: `index.html` + `assets/styles.css` + `assets/main.js`.
Ни зависимостей, ни шага компиляции — что в репозитории, то и в браузере.

## Локальный просмотр

```bash
python3 -m http.server 8777
```

Открыть <http://localhost:8777>. Файлы можно открывать и напрямую (`file://`),
но переключатели языка и темы используют `localStorage` — с локального сервера
поведение честнее.

## Как всё устроено

| Файл | Что внутри |
|---|---|
| `index.html` | весь контент, обе языковые версии рядом |
| `assets/styles.css` | токены тем и палитр, типографика, сетка, развороты, витрины, стенды |
| `assets/main.js` | язык, тема, палитра шапки, навигация, просмотр кадров, появление секций |
| `assets/labs.js` | подсветка кода и шесть живых стендов |
| `assets/shots/` | снимки экранов проектов: `<имя>.jpg` — полный кадр, `<имя>-t.jpg` — плитка |
| `tools/shots.sh` | пережимает PNG из headless Chrome в оба размера |
| `tools/og.html` + `og.sh` | шаблон и сборка `assets/og.jpg` — превью ссылки в мессенджерах |
| `tools/lead-proxy/` | приёмник заявок с формы — единственный кусок, которому нужен сервер |
| `assets/fonts/` | шрифты лежат у себя, а не на fonts.googleapis.com (см. `tools/fonts.sh`) |
| `404.html`, `robots.txt`, `sitemap.xml` | служебные файлы сайта |
| `.github/workflows/pages.yml` | публикация на GitHub Pages при пуше в `main` |

**Два языка.** Каждый переводимый блок продублирован с атрибутом `lang="ru"` /
`lang="en"`; CSS прячет неактивный по `:root[data-lang]`. Никакого словаря в JS —
текст правится прямо в разметке, рядом со своим переводом.

**Две темы.** Палитра описана переменными на `:root`, переопределяется в
`@media (prefers-color-scheme: dark)` и в `:root[data-theme="dark"|"light"]`.
Выбор пользователя сохраняется в `localStorage` и перебивает системную тему.

**Развороты кейсов.** Шесть `<article class="spread">` идут вертикальной
чередой во всю ширину окна, каждый в палитре своего продукта (`.pal-*`).
Липкая шапка забирает себе палитру того разворота, над которым стоит.

**Навигация.** Страница длиной в двадцать тысяч точек, поэтому у читателя
всегда есть три способа никуда не листать: разделы в шапке (`nav.nav`,
подсветка текущего — `aria-current`, ставит `main.js`), кнопка «Обсудить»
рядом с переключателями и переход «Следующий кейс →» внизу каждого разворота.
Ниже 58rem разделы и кнопка в шапку не влезают — там работает нижняя полоса
(`div.dock`): она выезжает, когда первый экран уехал вверх, и уходит, когда
контакты уже на экране.

**Живые стенды.** В каждом кейсе слева — фрагмент, скопированный из репозитория
проекта, справа — он же в работе: подвигайте ползунки или нажмите кнопку, и
строки кода, которые сейчас отработали, подсветятся. Для TypeScript-проектов в
браузере выполняется та же самая функция; для Python и SQL — её перенос на JS,
строка в строку (`app/domain/scheduling.py`, `bot.py`, `EXCLUDE`-ограничение).
Логика стендов — в `assets/labs.js`, каждый стенд отдельным блоком, разметка
привязывается через `data-lab`, `data-in`, `data-view`, `data-out`.

> Меняете код в проекте — поправьте и фрагмент в `index.html`. Смысл стендов
> в том, что там настоящий код; расхождение убивает весь эффект.

**Заявка.** В контактах есть форма из трёх полей: не все пишут первыми в
мессенджер. Отправлять её напрямую в Telegram нельзя — для этого нужен токен
бота, а всё, что попало в статику, попало и к читателю. Поэтому форма стучится
в маленький приёмник, `tools/lead-proxy/`. Пока `data-endpoint` у формы пуст,
`main.js` её не показывает вовсе: остаются Telegram, телефон и почта.

**Снимки экранов — настоящие.** Каждый проект был склонирован, собран и поднят
локально, экраны сняты headless-браузером в 2× и пережаты `tools/shots.sh`. Ни
один кадр не снят с боевого сервера; данные на всех экранах демонстрационные,
подставленные в локальной копии. Кадры с реальными контактами, телефонами и
адресами отбракованы и не публикуются.

Пересобрать после новых съёмок:

```bash
tools/shots.sh clean
```

**Витрина кейса.** Первый кадр — ведущий, он вдвое крупнее: на плитке размером с
марку плотный интерфейс превращается в серую кашу. Клик открывает кадр во весь
экран, листается стрелками и клавишами ←/→, закрывается Esc. Телефонные кадры
идут отдельной сеткой (`.shots--phone`) — у них другая пропорция.

**Цвет проекта.** У каждого кейса свой фирменный цвет, взятый из самого проекта.
Разворот целиком одет в него классом `.pal-*` — пара «фон/текст» там своя и от
темы читателя не зависит, поэтому контраст внутри разворота постоянен. В реестре
на первом экране тот же цвет приходит парой `--case-dark` / `--case-light` в
атрибуте `style`: два значения нужны потому, что винное золото театра нечитаемо
на светлой бумаге, а синий калькулятора смет — на тёмной.

## Что дописать перед публикацией

1. **Контакты и условия.** В секции `#contact` — Telegram, телефон, почта и три
   строки условий (`dl.terms`): первый разговор, срок первого этапа, схема
   оплаты. Меняются прямо в разметке. Телефон опубликован открыто — его будут
   собирать спам-боты; если это мешает, оставьте только Telegram.
2. **Приёмник заявок.** Форма в контактах спрятана, пока у неё нет адреса.
   Поднять `tools/lead-proxy/` (инструкция там же) и вписать адрес в
   `data-endpoint` у `form#lead` — только после этого форма появится на
   странице. Отдельно перечитайте раздел «Вопросы, которые задают»: там
   написано про права на код, месяц правок после запуска и сроки, и это
   публичные обещания — они должны совпадать с тем, как вы работаете.
3. **Ссылки на проекты.** Репозитории приватные, поэтому ссылок нет намеренно.
   Фрагменты кода на странице — единственное, что опубликовано; секретов,
   ключей и клиентских данных в них нет. Если какой-то проект станет публичным —
   добавить строку в `dl.spec` соответствующего кейса.
4. **Демо-данные в стендах.** Сертификаты театра, тексты постов и цена малярки
   (450 ₽/м²) — иллюстративные. Реальные цифры при желании подставляются в
   `assets/labs.js`.
5. **Границы работы.** Раздел «Чего я не делаю» написан по тому, как устроена
   работа в остальных разделах. Перечитайте: это публичный отказ от части
   заказов, и он должен совпадать с вашей реальной практикой.
6. **Домен.** Свой домен — в настройках Pages плюс файл `CNAME` в корне. После
   смены домена пересоберите превью — в `tools/og.html` и в мета-тегах
   `og:image` / `og:url` зашит адрес `artyomliske.github.io`.

## Обновление контента

Кейсы — блоки `<article class="spread">` в `index.html`. Каждый состоит из строки
метаданных, заголовка, витрины кадров, прозы («Было / Стало» либо «Задача /
Решение»), панели `dl.spec` с фактами, живого стенда и перехода к следующему
кейсу. Новый кейс — копия соседнего с заменой текста; порядок в разметке =
порядок на странице. Добавили кейс — поправьте `spread__next` у соседа и строку
в реестре на первом экране: обе ссылки прописаны руками.

Цифры в кейсах взяты из самих репозиториев (строки кода, эндпоинты, тесты,
миграции, коммиты) — при существенных изменениях проектов их стоит пересчитать.
