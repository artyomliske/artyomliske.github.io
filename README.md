# Портфолио — Артём Лиске

Одностраничный сайт-портфолио: автоматизация бизнес-процессов, шесть кейсов,
русская и английская версии, светлая и тёмная темы.

Статика без сборки: `index.html` + `assets/styles.css` + `assets/main.js`.
Ни зависимостей, ни шага компиляции — что в репозитории, то и в браузере.

## Локальный просмотр

```bash
python3 -m http.server 8777
```

Открыть <http://localhost:8777>. Файлы можно открывать и напрямую (`file://`),
но переключатели языка и темы используют `localStorage` — с локального сервера
поведение честнее.

## Как всё устроено

| Файл | Что внутри |
|---|---|
| `index.html` | весь контент, обе языковые версии рядом |
| `assets/styles.css` | токены тем, типографика, сетка, табло занятости |
| `assets/main.js` | язык, тема, анимация табло, появление секций |
| `.github/workflows/pages.yml` | публикация на GitHub Pages при пуше в `main` |

**Два языка.** Каждый переводимый блок продублирован с атрибутом `lang="ru"` /
`lang="en"`; CSS прячет неактивный по `:root[data-lang]`. Никакого словаря в JS —
текст правится прямо в разметке, рядом со своим переводом.

**Две темы.** Палитра описана переменными на `:root`, переопределяется в
`@media (prefers-color-scheme: dark)` и в `:root[data-theme="dark"|"light"]`.
Выбор пользователя сохраняется в `localStorage` и перебивает системную тему.

**Табло в шапке** — не картинка, а живая демонстрация правила из StudioCRM:
брони встают в линейку времени, пересекающая попытка отклоняется. Ширина блоков
задаётся переменными `--from` / `--to` прямо в разметке.

## Что дописать перед публикацией

1. **Контакты.** В секции `#contact` сейчас только почта. Telegram и телефон
   лежат готовым закомментированным блоком — раскомментировать и вписать свои.
2. **Ссылки на проекты.** Репозитории приватные, поэтому ссылок нет намеренно.
   Если какой-то проект станет публичным или получит витрину — добавить строку
   в `dl.spec` соответствующего кейса.
3. **Домен.** Свой домен — в настройках Pages плюс файл `CNAME` в корне.

## Обновление контента

Кейсы — блоки `<article class="case">` в `index.html`. Каждый состоит из строки
метаданных, заголовка, прозы («Было / Стало» либо «Задача / Решение») и панели
`dl.spec` с фактами. Новый кейс — копия соседнего с заменой текста; порядок в
разметке = порядок на странице.

Цифры в кейсах взяты из самих репозиториев (строки кода, эндпоинты, тесты,
миграции, коммиты) — при существенных изменениях проектов их стоит пересчитать.
